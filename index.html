The through-line

Most demos need a person standing next to them.

I keep building the version that doesn't. A pull request gets flagged, rewritten in a sandbox, retested, and merged with no reviewer in the loop. A spoken sentence becomes G-code on a printer bed. A signal fires and a position opens, sized by an expectancy figure I can defend with a permutation test.

I study cybersecurity at Purdue, which is where the paranoia comes from. An agent with real permissions needs allow-lists, sandboxes, and a way to prove it was right, so I care as much about the evidence a system produces as the action it takes.

The habit predates the code. I started slacklining at eight, spent a summer falling off a line in a public park, and fixed it by drilling the basics on a schedule until the hard version stopped being hard. Wrestling rewarded that. So did the Eagle project. I trust a process I can repeat over a result I got once.

Brailed

ESP32 · BLE · Jac JacHacks SF · 2nd Place, Social Impact

A phone-mounted braille keyboard that lets blind, deaf, and deafblind users type, read captions, and drive a phone privately. Refreshable braille displays start above $1,000. This one is about $15 in parts.

  1. 6-key chord
  2. decode on release
  3. BLE GATT
  4. phone app
  5. Jac + byLLM
  6. phone action
Devpost ↗
▸Read the build story
The hardest bug wasn't code

The ESP32 kept resetting in a loop. BLE radio bursts landing on top of an OLED refresh sagged the supply voltage far enough to trip the brownout detector: a hardware failure wearing a software costume. I stripped the firmware back to a bare heartbeat sketch to isolate it, then fixed power delivery and dropped the CPU clock. The tempting fix was to disable the detector, which hides the problem instead of solving it.

The decision I'd defend

Send started as an all-six-keys chord. Elegant, and wrong: six pads in one debounce window is six chances at a false negative, and a silently dropped Send is the worst failure for someone who can't glance at the screen. I moved it to a dedicated seventh button, re-deriving what Perkins braillers settled decades ago. A mistyped letter is a typo. A dropped Send is a broken promise.

How it works
  • Six sensors read as a 6-bit chord, decoded on release: a state machine accumulates dots while any key is held and looks up the bitmask once all fingers lift, so imperfect timing still registers as one character
  • A custom BLE GATT service carries characters out and transcript text back, on separate characteristics
  • Plain typing never leaves the BLE link; only command-mode input goes through the Jac/byLLM pipeline, so the LLM adds no latency to normal use

Trading Agent

Python Runs unattended

An autonomous quant fund that scores 196 assets across ten signal engines and trades only setups whose edge survives a permutation test. Not a pretty equity curve: p = 0.001 across 1,998 trades, harness included.

  1. 10 signal phases
  2. research layer ±25
  3. master score
  4. 70-point gate
  5. risk gates
  6. bracket execution
  7. Telegram
GitHub ↗
▸Read the build story
The trade it refused

A name came through at 92 technical, everything the chart layer wants. The research layer pulled SEC EDGAR Form 4 filings, found a $271M insider sell-off underneath, and the agent declined. That refusal is the design: technicals are a hypothesis, and research can veto them by ±25 points before the risk gates ever see it.

Proof, not a backtest screenshot
  • Walk-forward out-of-sample folds, permutation tests, Probabilistic and Deflated Sharpe, bootstrap p-values, and Benjamini-Hochberg FDR correction, all shipped in the repo rather than described in a slide
  • 1,998 trades, +0.455R expectancy, +3.28R average win against −1.06R average loss, 79% of symbols net profitable
  • The README states the unflattering half too: the edge is real but the return profile is defensive, and the bottleneck is capital efficiency rather than signal quality
How it runs
  • Ten phases per symbol per scan: ~60 technical indicators, Hurst and ADF statistics, regime classification, cross-timeframe confluence from 15m to 1w, and an XGBoost/RandomForest ensemble treated as a weak prior rather than an oracle
  • A 70-point gate plus relative-strength veto before any position is sized
  • Correlation caps, a portfolio-heat ceiling, and a kill switch that flattens the book
  • Sentiment and multi-timeframe phases score neutral in backtests because they need live feeds, so they aren't point-in-time reproducible and the harness says so

Two paths, one printer

The kiosk runs on an Orange Pi 5 Pro: hold the mic, describe an object, and Meshy returns a model that spins in Three.js while ElevenLabs narrates. Morph-Forge takes the harder route. It looks up real pipe dimensions and PLA tensile figures with citations first, so Llama-3.3-70B writes parametric OpenSCAD against measured numbers rather than hallucinated ones, then reviews its own output before printing.

The failure mode I documented instead of hiding

Both modes write to the same scratch gcode path, so a second kiosk tab wipes a finished build. Instead of papering over it, the export endpoint re-checks the file on disk rather than trusting an in-memory flag. The failure surfaces as a clean 409, never as a USB stick holding the wrong object. The real fix is per-build paths, and the README says it's deferred.

VIGIL

Eldercare · Vision Best Use of Postgres Private repo

An eldercare guardian that reads 847K behavioral events at sub-100ms latency from a single camera, catching falls and anomalies before they become emergencies, then calling the family itself.

  1. one camera
  2. YOLO + MediaPipe
  3. Postgres NOTIFY
  4. ClickHouse baseline
  5. anomaly detected
  6. Claude phone call
▸Read the build story
Two databases, two jobs

Postgres owns the people and the rules: who the resident is, who to call, what counts as an alert. ClickHouse owns the behavior: 847K events over 30 days, with a rolling window computing each person's own baseline per activity per hour. A fall doesn't wait for analytics. An INSERT trigger fires pg_notify and the alert lands in under 200ms.

Baseline, not raw frames
  • Anomaly is measured in standard deviations from that person's own history, not against a generic threshold
  • Events batch 64 at a time and CLIP embeddings compute every 15th frame, because writing every frame would stall the camera loop
  • Vector search and time-series analytics live in the same system, so there's no separate vector DB to keep in sync

What it does

Sales tools tell you a deal died after it dies. DealGhost learns each team's own loss signatures from their historical calls, then intervenes while the deal is still open.

How it runs
  • Trained on the team's own data, not a generic playbook
  • Continuously compares live deals against known loss patterns
  • Intervention is automatic, not a weekly report
